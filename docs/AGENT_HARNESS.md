# Agent Harness：执行与修订约束

Harness 的目标是让工作流有效修复并完成交付。执行记录只提供证据，不能替代修复和独立验收。

## 当前接入范围

- 所有智能体工具调用沿用 `server/agent/tool_harness.py` 的参数错误分类、重复失败预算、工具回执，以及现有超时、取消和写入权限控制。
- 实验设计的五个代码实现阶段接入 `server/agent/execution_harness.py`，由 `implementation_attempt_harness.py` 连接现有调度器。
- 代码审查接入 `implementation_review_followup.py`，逐项核对前一份有效审查的源码问题。
- 节点界面、科研能力、模型配置和现有六轮修订预算保持原有产品选择。

## 对稳定运行的具体约束

1. 调用前保存准确的写入范围、待修问题、输入与提示摘要、工具权限及步数上限。失败则不调用模型。
2. 调用后执行现有文件所有权与实现校验，保存每个文件的前后摘要及实际变化；完成回执保存失败则不发布阶段接受事件。
3. 静态通过只记为 `awaiting_review`。独立审查绑定同一源码快照后才能记为 `review_passed`；旧快照记为 `superseded`。
4. 修订会话身份同时绑定输入和审查问题。新问题不能复用面向旧问题的会话身份。
5. 审查保留未解决问题的原 ID；已解决或被推翻的问题必须在 `resolved_findings` 中给出当前源码证据。遗漏、改名、相互矛盾的结论不能被算作修复进展。
6. 漏查时最多自动续做一次只读审查，不消耗作者修订轮次。仍不完整时使用已有审查中断流程保留问题，不编造通过结论。
7. 取消和异常记录为 `interrupted`；进程骤停可能留下 `running`。这些记录不允许自动重放有副作用的工具；恢复仍须走现有任务、进程与产物核对流程。

记录位于项目 `.merak/harness/<运行 ID 的摘要>/<尝试 ID>.json`。它们是运行时证据，不是第二套权威任务状态库；任务状态仍由现有运行状态管理器维护。模型没有写这些记录的权限。

## 验证范围

`npm run test:agent-harness` 包含原有工具边界测试，以及执行记录写盘失败、取消、审查变化、旧快照、跨任务隔离、问题改名、漏查后有界续审和会话身份更新回归。

测试使用临时项目和替代模型响应，不执行训练或调用模型。它们不能证明真实科研工作流已经稳定。真实验收仍需固定候选源码/模型，以正常工作流恢复失败样本并完成论文和后续交付；不得手工补产物或改验收状态。

新执行回执目前接入代码实现阶段，其他节点继续使用原有运行记录。报告修订增加预算耗尽后的编辑交接和来源证据反驳；后续扩展使用同一执行层，不能建立第二套修订调度器。

本次源码验证（2026-10-31）：`npm run test:agent-harness` 161 项通过；实现恢复、审查、阶段目标和修订签名的定向回归 398 项通过；`npm run verify:local` 通过（含 168 项 Python 测试）。严格代码规范检查与 `git diff --check` 通过。这些计数不代表真实模型全链验收完成。

2026-11-01 已完成一个真实模型项目的 13 节点恢复交付；它经过此前开发修复，不是全新跨领域任务连续稳定完成的证明。发布验证范围见 [0.1.2 版本说明](RELEASE_0.1.2.md)。
