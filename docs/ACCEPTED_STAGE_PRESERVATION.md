# 已验收阶段保留与恢复

`done` 表示阶段执行结束，`accepted` 表示产物通过对应检查；两个状态不能互换。
恢复时核对输入、产物、审查身份和版本绑定，从仍需处理的阶段继续。

## 依赖边界

- 科研输入或产物变化：显示具体文件差异，重新验证声明依赖这些文件的阶段。
- 校验实现变化：先重新检查原有产物；不能仅因代码维护就要求模型重写科学内容。
- 下游标题、披露或布局变化：刷新对应展示产物及必要检查。
- 新审稿问题：保留既有通过项，将问题交给明确的产物负责人。
- 工作流完成后：局部修改保存为独立修订，原交付保持为历史记录；重新执行由用户发起。

例如，叙事只使用模拟策略的 schema 常量时，其输入身份绑定该常量，不应额外
依赖同模块的图注、披露文本和渲染版本。数据 schema 或主张计算变化仍需要复核。

## 复用证据

复用已验收阶段需要同一运行中的有效快照、完整科研来源清单、原文与构建记录
相符，以及当前检查通过。文件变化、记录缺失或运行身份不符时不能复用。
复用不意味着删除失败记录、重签旧格式验收，或把科研限制视为已解决。

## 验证

相关回归覆盖叙事策略依赖范围、已验收阶段重验证、外部文件修改和完成状态只读。
参见 `test_narrative_policy_scope.py`、`test_narrative_accepted_upgrade.py` 和
`test_completed_state_readonly.py`。纯测试通过不等于跨项目稳定性验收完成，
发布状态见 [版本说明](RELEASE_0.1.2.md)。
