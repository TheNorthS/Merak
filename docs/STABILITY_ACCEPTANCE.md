# 稳定性验收

软件启动、流程完成和科研结论质量分别验证，不互相替代。
当前版本的实际完成情况见 [0.1.1 发布说明](RELEASE_0.1.1.md)。

## 验收门槛

1. 固定源码、技能、模型配置和候选包，记录内容摘要。
2. 同一候选连续完成三个不同研究方向的新项目，运行期间不修改软件源码、
   不手工补产物、不修改运行状态。使用真实计算或用户明确选择的证据模式。
3. 验证模型超时、断流、重复事件、并发文件修改、磁盘写入失败、进程崩溃、
   应用重启、预算耗尽、取消及子进程回收。结果不明的副作用不得自动重复。
4. 中断恢复保留仍然有效的产物，界面终态与持久化状态一致。
5. 完成后的局部修订保留原交付，不擅自启动科研工作流。
6. 验证安装、升级、配置保留及打包后程序的实际使用路径。

保留所有失败样本。生产实现变化后重新冻结候选；不得降低门槛、改状态或
伪造结果取得通过。模拟研究必须披露数据生成假设、种子和结论边界。

## 验证工具

- `npm run verify:local`：类型、代码规范和定向离线回归。
- `npm run test:packaging`：构建与启动契约测试。
- `npm run verify:package`：打包后端和桌面基础能力检查。
- `scripts/verify_stability_live.py`、`scripts/verify_stability_resume.py`：
  显式授权后的真实模型验收与恢复。
- `scripts/verify_stability_evidence.py`：验收报告与候选包身份核对。

本地运行记录位于被 Git 忽略的 `output/`、用户项目和 `release/` 中。
凭据、模型密钥、数据库和完整模型会话不应随源码发布。版本说明应保留结论
与未完成事项，但不包含个人路径、私有端点或原始科研资料。
