# Domain Results Analysis

Write the canonical `experiments/results/analysis.md`.

## Procedure

1. Read the publication profile, selected idea, method contract, domain methodology, statistical analysis plan, domain validation plan, raw logs, result manifests, exclusions, and provenance.
2. Determine whether evidence is executed, imported, secondary, planned, synthetic preview, or absent. Never promote a template, dry run, demo value, or layout preview to scientific evidence.
3. Analyze the declared primary estimand or theorem/qualitative question first. Respect the independent analysis unit, pairing, clustering, repeated measures, censoring, batch structure, missingness, multiplicity, and preregistered exclusions.
4. Report effect estimates or guarantees with uncertainty and denominators. For predictive work include calibration and external or shift validation; for systems include tails, scale, failures, resources, and cost; for omics include QC and adjusted significance; for qualitative work bind themes to traceable excerpts, negative cases, triangulation, and reflexivity.
5. Test alternative explanations and falsification conditions before supporting a claim. Separate supported, contradicted, unresolved, and out-of-scope claims.
6. Record sensitivity analyses, failed runs/checks, missing evidence, deviations from plan, and the minimum next evidence required.

Do not invent values, p-values, confidence intervals, samples, themes, proof status, or successful execution. If no measured evidence exists, produce a planned-analysis contract explicitly labeled NOT EVIDENCE.
